# Evidence-linked learning and deferred reflection

Strategy exposure is no longer treated as proof of use or success. Optional reflection assesses observable use and must quote a real passage from the answer. The server validates the strategy key and passage. This remains model-assessed application, not causal proof. Feedback is eligible only for the same conversation and matching preceding response within 24 hours. Ambiguous feedback across multiple applied strategies is left unscored; a uniquely named strategy may receive credit. A database transaction consumes each feedback turn once and updates the strategy together with its use record. Neutral feedback cannot increase trials, confidence or maturity. One slot allows least-recently-exposed challengers to compete with established priors.

Preferences retain active records with source, observation time and turn ID, plus bounded supersession history. Explicit first-person corrections replace the same recognized communication dimension (length, tone or format); older retrieved memories cannot undo them. Unknown subjects stay independent rather than guessing a contradiction. New preferences survive a full legacy profile. Fiction and blocked categories are excluded. This is a bounded preference model, not general semantic contradiction resolution.

Optional reflection is enqueued only for the existing triggers and retains the turn's remaining supplemental compute allowance. Required conversation, action and cognitive persistence still completes before the API response. After sending JSON, the API uses Vercel `waitUntil` to drain at most one queued job. There are no new schedules or polling loops. One running job per user and a unique user/turn key prevent duplicate execution. Queued work can resume on the next enabled owner chat; it is not a continuously running worker. Interrupted running jobs are marked failed rather than risking another billable request of unknown completion. Receipt states distinguish queued, running, completed, skipped and failed. Provider usage is recorded by the job. Private inputs are cleared on completion/failure; expired queued inputs and old receipts are cleaned on subsequent drains.

The reflection table and RPCs are service-role only. RLS is enabled with no client policies deliberately: anonymous and authenticated clients have no grants. The additive migration must be applied before deploying this code. Existing strategy scores are retained; historical noisy feedback is not retroactively relabeled.

Verification: behavioral tests cover correction parsing, challenger selection, same-thread attribution, ambiguous applications, preference supersession/privacy, durable job receipts and a stalled reflection provider after successful API delivery. A rollback-only database probe verifies atomic feedback, duplicate rejection, exclusive job claiming and client access denial. No live model quality uplift or latency percentage is claimed by these checks.
