# Owner harness comparison pilot

Open `/ari-harness-comparison.html` while signed into the configured owner account.
Run the six cases three times each (18 pairs / 36 paid calls), rate A/B/tie/neither
before revealing labels, and download the JSON for analysis. Start with one pair
to confirm provider compatibility. There is no automatic background execution.

Both candidates use `gpt-6.1-sol`, high reasoning effort, 4096 maximum output tokens,
fresh independent responses, the exact same serialized input, and no tools. Model
fallback is prohibited. Execution and presentation orders are randomized separately.
Incomplete, empty, mismatched-model, and failed responses invalidate the pair.
Input hashes, commit, prompt sizes, actual usage, status, answers, and latency are
retained. Model output uses textContent in the UI. Raw provider secrets are never
returned. Labels are hidden by presentation, not cryptographically inaccessible to
the owner; inspect only after rating if you want a blind personal preference test.

## Scope and interpretation

This measures the current deterministic prompt layers generated by Ari's actual
orchestrator versus a basic assistant with the same safety context. Synthetic
self-contained tasks avoid unequal access to personal facts. Preparation runs
before any primary provider call, council, tool action, or persistence. It includes
Companion, Coordinator, Executive/metacognition and Deliberation instructions but
does NOT hydrate personal memories, run advisers/council, repair responses, execute
tools, or advance persistent cognition. It is NOT a full production runtime or
longitudinal learning benchmark. Do not call this a comparison of all Ari abilities.

The six cases cover changed constraints, debugging, evidence, probability, creative
constraints, and calibrated uncertainty. The exact probability answer is 1/3:
3 red-red combinations out of the 9 combinations containing at least one red.
Other cases should be evaluated against the supplied prompt, without invented facts.
Count neither votes and failures separately. Compare costs and latency by case;
aggregate preferences only across the same version/commit. Three repeats are a
small exploratory pilot, not a statistically established overall ranking.

## Storage and operations

Apply `scripts/ari-harness-comparison-schema.sql` with the Supabase migration tool.
The table has RLS enabled and no client-role grants. Only the service role can read
or write it; the HTTP endpoint checks the authenticated user against ARI_OWNER_USER_ID.
The reservation RPC is security-invoker and service-role-only, uses a transaction
advisory lock, and allows at most 24 pairs per owner per UTC day. A repeated trial ID
never launches another pair. Interrupted rows remain running for inspection; there
is no automatic retry or reclaim that could double-charge a long-running request.
No changes to ordinary chat, tool permissions, memory stores, or background jobs.

Run `node --test tests/ari-harness-comparison.test.mjs` for provider parity, failure,
owner access, and real prompt-preparation integration checks.
